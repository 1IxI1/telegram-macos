# WalletEngine

Swift bindings for the `wallet-engine` Rust library used by the TON wallet
(same library and module layout as telegram-ios).

- `Sources/WalletEngineFFI/WalletEngineFFI.swift` — UniFFI-generated Swift
  wrapper (checked in; regenerated by the build below).
- `wallet_engineFFI.xcframework` — static `libwallet_engine.a` (arm64 + x86_64,
  macOS 11+) with the generated C header and modulemap. Not checked in; built
  locally like every other native dependency.

Both artifacts are produced by the `WalletEngine` core-xproject, so the normal

```shell
./scripts/configure_frameworks.sh
```

builds them alongside OpenSSL, ffmpeg, webrtc, tde2e and the rest. The build is
skipped when the artifacts are already present, and re-runs when
`core-xprojects/wallet-engine/build` or the xcframework is missing (so the
`scripts/rebuild` flag forces a rebuild the same way it does for the others).

To rebuild only this dependency:

```shell
sh core-xprojects/wallet-engine/wallet-engine/build.sh \
  submodules/telegram-ios/third-party/wallet-engine/wallet-engine \
  core-xprojects/wallet-engine/build \
  packages/WalletEngine
```

Requirements: the wallet-engine submodule, and a Rust toolchain (rustup installs
the version pinned in the engine's `rust-toolchain.toml` automatically):

```shell
git -C submodules/telegram-ios submodule update --init third-party/wallet-engine/wallet-engine
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --no-modify-path --profile minimal
```
