MtProtoKit security findings

Why this matters for the macOS app. The Rust engine runs with generate_key = 0 (RustNetworkSession.swift:191). MtProtoKit therefore still creates every auth key and binds every temp key, over its own TCP transport, through the user's proxy if one is set.

An attacker can force a new key exchange at any time with a forged, unauthenticated -404 frame (obfuscated2 is not authenticated). Key exchanges also happen when a temp key expires (24 h) and for every new DC, media or CDN connection.

So every pre-authentication bug below can be triggered on demand by an on-path network attacker or the operator of a configured MTProxy or SOCKS proxy. MtProtoKit is also used by Telegram iOS.

High

High F1 · Remote crash in server_DH_params_ok padding removal

The only length guard is answerWithHash.length < 20. With a 32-byte encrypted_answer, answerData holds 12 bytes, and the loop removes one trailing byte up to 16 times with NSMakeRange(answerData.length - 1, 1). At iteration 12 the range becomes {NSUIntegerMax, 1} and Foundation throws NSRangeException. Nothing on the MTProto queue catches it, so the app aborts.

Attacker needs
Only the plaintext nonce and server_nonce (visible in req_DH_params) plus any 32-byte blob. The SHA1 check never gets a chance to reject it.
tdlib
Parses the TL, requires padding < 16, and cannot crash (Handshake.cpp:186-212).
Reproduced
Running the exact loop on a 12-byte NSMutableData aborts with "range {18446744073709551615, 1} causes integer overflow".
Fix
Stop when answerData.length == 0. Better, parse server_DH_inner_data from offset 20, require padding < 16, then SHA1 the parsed span.

High F2 · Remote crash or hang from pq = 0 or 1

pq is folded into a uint64_t with no length check: an empty string gives 0, and more than 8 bytes is truncated. MTFactorize then evaluates % what (division by zero for pq = 0), % (what - 1) (division by zero for pq = 1) and 1 << (i + 18) (undefined once i ≥ 13). There is no pq ≤ 2^63 guard.

Intel (x86_64)
pq = 0 and pq = 1 both exit with SIGFPE (status 136). The app ships universal, so Intel Macs crash.
Apple Silicon
At -Os/-O2, the Release defaults, % what lets clang assume what != 0, and it removes the zero guard in mygcd. pq = 0 then spins forever.
Effect
MTFactorize runs on [MTProto managerQueue], a single serial queue for the whole process. The hang freezes every MtProtoKit MTProto: all key creation and binding stop.
Attacker needs
To echo the plaintext nonce and list the public production fingerprint. A 63-bit prime pq also costs about 0.6 s of CPU per attempt, and the attacker can repeat it (see F3).
tdlib
Returns early for pq <= 2 || pq > 2^63, caps the shift with min(5, i), checks pq % p, and has a separate bignum path (tdutils/td/utils/crypto.cpp:103-139, 243-246).
Fix
Reject pq.length == 0 || > 8, pq <= 3 and pq > 2^63 before factorizing. Cap the shift, and verify p * q == pq.

Medium

Medium F3 · No backoff after a failed handshake

Every failed check calls reset:, which closes the connection and asks for a new transaction at once. The transport backoff resets to 0 on any non-error frame received in unauthorized mode, and the first reconnect is immediate.

So a hostile server or man in the middle can drive connect → req_pq → bad answer → reconnect at network round-trip speed, and choose the CPU cost of each round:

  • about 0.6 s for a 63-bit prime pq;
  • fingerprint recomputation inside a double loop;
  • for pq longer than 8 bytes, req_pq is re-sent with the same nonce and no reset at all.
tdlib
Rate-limits new connections per DC with FloodControlStrict (ConnectionCreator.cpp:102-115, 997-1006).
Fix
Count handshake failures per DC and feed them into MTRetryDelayForFailureCount. Do not count unauthorized frames as valid data until dh_gen_ok. Precompute the key fingerprints.

Low

Low F4 · auth_key not padded to 256 bytes

BN_bn2bin returns the minimal length. In about 1 in 256 handshakes the key is shorter, so auth_key_id and auth_key_aux_hash don't match the server, and the handshake restarts. The server is left holding an orphan key. tdlib uses to_binary(256). Fix: left-pad g_ab and g_b to 256 bytes.

Low F5 · g_b not range-checked

The docs require 1 < g_b < p−1, and tdlib also applies the 2^(2048−64) bounds (DhHandshake.cpp:95-126). MTCheckIsSafeB exists but is unused. This matters mostly as a guard against RNG failure (F6). Fix: check g_b with the same bounds as g_a.

Low F6 · RNG failures ignored

The SecRandomCopyBytes return value is discarded for nonce, new_nonce and b, so on failure uninitialized bytes would become secrets. tdlib aborts. encryptRSAModernPadding already checks correctly. Fix: fail the handshake on RNG failure.

Low F7 · Legacy inner-data constructors

The code uses p_q_inner_data#83c95aec / p_q_inner_data_temp#3c6a84d4 without dc; the docs and tdlib use _dc#a9f55f95 / _temp_dc#56fddf88. Without dc the server cannot detect a handshake redirected to another DC. Fix: switch to the _dc variants (dc negative for media, +10000 on test).

Low F8 · server_time and initial salt discarded

No time difference is set from the handshake. The computed server_salt is dropped and salt 0 is stored, so every new key's first message costs a bad_server_salt round trip. tdlib stores both. Fix: store the salt and server_time − now.

Low F9 · No temp-key rotation

Expiry is enforced only when the keychain loads. A long-running process uses the key until the server rejects it, so there is a stall about every 24 h, and recovery goes through the -404 path. auth.dropTempAuthKeys is never called. tdlib rotates 1 h early and drops superseded keys. Fix: rotate ahead of expiry and drop old keys.

Low F10 · bind expires_at from bind time

expires_at = globalTime + 86400 is taken at bind time, so it can be later than the server's real expiry by up to the retry backoff. tdlib uses the key's own expiry. Fix: tie it to the handshake time.

Low F11 · Bind-failure handling

Every bind retry runs a full new DH. ENCRYPTED_MESSAGE_INVALID stops retries without validating the permanent key. If the permanent key disappears during the temp handshake, the action never completes and blocks new actions for that selector. tdlib keeps the temp key, re-sends only the bind, and validates the main key. Fix: follow tdlib Session.cpp:383-441.

Low F12 · Forged -404 completes a media bind

handleMissingKey calls complete on the bind service, so the temp key is stored as bound. Requests then fail with AUTH_KEY_PERM_EMPTY, which triggers another drop and regenerate, giving an attacker a loop trigger. Fix: remove the "-404 means bind success" special case.

Low F13 · CDN RSA key handling

If no fingerprint matches, the single CDN key is used anyway. It is still trusted, but CDN keys are never refreshed. There is no 2048-bit modulus check, so a short modulus makes the RSA_PAD while (true) loop effectively endless; only a malicious server can supply CDN keys. tdlib refuses non-256-byte keys and refetches. Fix: require 2048 bits, refetch on mismatch, and bound the loop.

Info

Info F14 · Static scratch buffer in MTRsaFingerprint

Not thread-safe if fingerprints are computed concurrently.

Info F15 · Decrypted plaintext in logs

On a parse error, dumpHexString logs up to 128 bytes of decrypted plaintext into MTLog and MTShortLog. It is not key material.
